# CONTENT_GUIDE.md — Руководство по добавлению контента в Yomizora

Это руководство предназначено для ИИ-агентов и авторов контента. Оно описывает, как создавать и импортировать новые японские тексты в приложение **Yomizora** без изменения программного кода и без перекомпиляции APK.

---

## 1. Принцип отделения контента от кода

Весь учебный контент хранится в формате JSON и загружается в локальную базу данных `yomizora_content.db` через `ContentImporter`.
Пользовательский прогресс (`yomizora_progress.db`) **полностью отделён** от контента:
- Импорт новых пакетов не сбрасывает прогресс, избранное или сохранённые слова.
- Существующие тексты обновляются только при увеличении поля `"version"`.
- Стабильные идентификаторы `"id"` сохраняют привязку к прогрессу пользователя.

---

## 2. Структура JSON-пакета контента

Корневой объект пакета:

```json
{
  "pack_id": "custom_n5_pack_01",
  "pack_version": 1,
  "materials": [ ... ],
  "dictionary": [ ... ]
}
```

### Поля материала (`materials[]`)

| Поле | Тип | Обязательно | Описание |
|---|---|---|---|
| `id` | `string` | Да | Уникальный ID (`^[a-z0-9_]{3,64}$`), например `n5_story_056` |
| `order_index` | `int?` | Нет | Порядковый номер в уровне. Если не указан, добавляется в конец уровня |
| `level` | `string` | Да | Уровень JLPT: `N5`, `N4`, `N3`, `N2`, `N1` |
| `category` | `string` | Да | Категория (`Stories`, `Daily Life`, `Dialogues`, `News`, `Japanese Culture`, `Fairy Tales`, `Humor`, `Interesting Facts`, `Travel`, `Food`, `Education`) |
| `title` | `string` | Да | Заголовок на японском языке (уникальный в пределах уровня) |
| `description` | `string` | Да | Краткое описание на русском языке |
| `content_type` | `string` | Да | `"original"` или `"adapted"` |
| `source` | `string` | Да | Источник / происхождение |
| `author` | `string?` | Нет | Автор материала |
| `license` | `string` | Да | Лицензия (например, `"CC-BY-4.0 / Original"`) |
| `created_at` | `string` | Да | Дата создания (`YYYY-MM-DD`) |
| `version` | `int` | Да | Версия материала (`>= 1`). Для обновления существующего текста увеличьте версию |
| `paragraphs` | `array` | Да | Массив абзацев (`paragraphs -> sentences -> segments`) |
| `questions` | `array` | Да | От 1 до 3 проверочных вопросов формата Multiple Choice |

---

## 3. Правила фуриганы (`segments`)

Каждый абзац состоит из предложений (`sentences`), а каждое предложение — из сегментов (`segments`):

```json
{
  "text": "勉強",
  "reading": "べんきょう",
  "dict_id": "d_benkyou"
}
```

1. **Каждый сегмент, содержащий хотя бы один кандзи**, обязан иметь непустое поле `"reading"` с чтением хираганой. `ContentValidator` отклонит материал с кандзи без `reading`.
2. **Сегменты только из каны или пунктуации** должны иметь `"reading": null`.
3. Для глаголов и прилагательных с окуриганой отделяйте основу кандзи от окуриганы:
   - Правильно: `{"text": "食", "reading": "た"}`, `{"text": "べます。", "reading": null}`
   - Правильно: `{"text": "新", "reading": "あたら"}`, `{"text": "しい", "reading": null}`
4. Учитывайте контекстное чтение (например: `今日` -> `きょう`, `一日` -> `いちにち` или `ついたち`).
5. При наличии словарной статьи в `dictionary[]` указывайте `"dict_id"`, чтобы при нажатии на слово открывалась точная карточка перевода.

## 4. Требования к уровням JLPT

- **JLPT N5**: базовая лексика и грамматика (`です/ます`, частицы `は/が/を/に/で/へ/と/も/の`, прилагательные `い/な`, базовые глаголы, `～て` форма, `～たい`, `～ない`). Короткие, ясные предложения.
- **JLPT N4**: заметно более сложная грамматика и лексика (`～てみる`, `～ておく`, `～てしまう`, `～つもり`, `～かもしれない`, `～たら/ば/なら`, `～ようにする/なる`, `～そうだ/ようだ`, пассив/потенциал/побудительный залог, сложные придаточные предложения).
- **N3–N1**: поддерживаются архитектурой (`JlptLevel` enum и БД), могут быть добавлены аналогичными пакетами.

---

## 5. Правила проверочных вопросов (`questions[]`)

- От **1 до 3** вопросов на каждый текст.
- От **3 до 4** вариантов ответа (`options`).
- `correct_answer` — индекс правильного ответа (начиная с `0`).
- Поле `explanation` обязательно и должно понятно объяснять, почему ответ верный.
- Желательно указывать `reference_excerpt` — точную цитату из текста.
- Вопросы должны проверять понимание смысла, фактов, причин и следствий, а не угадывание.

---

## 6. Механизм проверки уникальности

`ContentValidator` и `ContentImporter` автоматически проверяют:
1. Уникальность `id` (`^[a-z0-9_]{3,64}$`).
2. Отсутствие дубликата заголовка (`title`) в рамках одного уровня JLPT.
3. Точное совпадение нормализованного японского текста (SHA-256 от текста без пробелов и пунктуации).
4. Близость текстов по коэффициенту Жаккара на 3-граммах символов (порог `0.85` — похожие тексты отклоняются).
5. Отсутствие дублирующихся вопросов внутри материала.

---

## 7. Способы добавления нового контента

### Способ А: Импорт прямо в установленное приложение (без перекомпиляции)
1. Подготовьте JSON-файл по образцу `examples/sample_content_pack.json`.
2. Передайте файл на Android-устройство.
3. Откройте **Настройки → Импортировать пакет контента (JSON)** и выберите файл.
4. Приложение проверит структуру, уникальность и фуригану, добавит материалы в локальную базу и покажет отчёт об импорте.

### Способ Б: Встраивание в стартовую поставку (assets)
1. Поместите новый пакет в `app/src/main/assets/content/` (например, `03_n5_extra_pack.json`) с уникальным `pack_id`.
2. При следующем запуске `ContentBootstrapManager` автоматически импортирует новый пакет.
3. Для проверки запустите `gradle testDebugUnitTest` — тест `ContentValidatorTest` проверит все JSON-пакеты в `assets/content/`.
